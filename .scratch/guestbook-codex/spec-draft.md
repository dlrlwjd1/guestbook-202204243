# Spec draft: Codex 인터뷰에 따른 방명록 보완

Status: deferred — 사용자 요청으로 개발 제외

## Problem Statement

기존 방명록은 배포되었으나 정식 grilling 인터뷰 없이 일부 정책이 정해졌다.
사용자가 Codex 대체 사용을 승인했으므로 실제 인터뷰 결정과 구현·검증의
연결을 기록하고, 방문자가 글별 비밀번호 정책을 이해하도록 보완한다.

## Solution

기존 공개 앱을 유지하며 확정된 정책을 명세에 반영한다. 글 작성 폼에서
비밀번호 분실 시 복구할 수 없음을 안내하고, 동명이인의 글도 서로 다른
글 비밀번호로 관리되는지 실제 서비스 동작을 검증한다.

## User Stories

1. 방문자로서 로그인 없이 글을 작성하여 인사를 남기고 싶다.
2. 방문자로서 중복 가능한 이름을 사용하여 원하는 호칭을 표시하고 싶다.
3. 방문자로서 이름·메시지·비밀번호의 입력 제한을 알아 유효한 글을 작성하고 싶다.
4. 방문자로서 공백뿐인 이름과 메시지를 거부하는 안내를 받아 입력을 고치고 싶다.
5. 방문자로서 이름·메시지 바깥 공백이 정리되어 글을 깔끔히 표시하고 싶다.
6. 작성자로서 비밀번호 공백이 보존되어 입력한 그대로 권한을 확인하고 싶다.
7. 방문자로서 비밀번호 분실 시 복구되지 않음을 작성 전에 알고 싶다.
8. 방문자로서 전체 글의 이름·메시지·작성 시각을 최신 작성 순으로 보고 싶다.
9. 작성자로서 올바른 글 비밀번호로 메시지만 수정하고 싶다.
10. 작성자로서 수정 뒤에도 이름·작성 시각·정렬 순서를 유지하고 싶다.
11. 작성자로서 확인창과 올바른 글 비밀번호로 내 글을 삭제하고 싶다.
12. 작성자로서 다른 글의 비밀번호나 틀린 비밀번호로 내 글이 수정·삭제되지 않길 원한다.
13. 방문자로서 수정·삭제 실패 이유를 화면에서 알아 다시 입력하고 싶다.
14. 방문자로서 새로고침 후에도 저장된 글과 수정·삭제 결과를 확인하고 싶다.
15. 방문자로서 기존 디자인을 PC·모바일에서 사용하고 버튼으로 목록을 갱신하고 싶다.
16. 채점자로서 이기정·202204243 표시와 공개 저장소·배포 URL을 확인하고 싶다.
17. 개발자로서 Codex 스킬 적용 기록에서 과거 작업과 이번 보완을 구분하고 싶다.

## Implementation Decisions

- Next.js App Router + TypeScript, Neon Postgres, Vercel과 기존 공개 URL 유지.
- 동일 이름 허용. 비밀번호는 글 단위이며 계정·관리자·복구 기능은 추가하지 않음.
- 이름 1~30자, 메시지 1~1000자, 비밀번호 4~128자. 기존 공백 처리 유지.
- 작성 폼의 기존 비밀번호 설명에 분실·복구 불가 안내를 추가하고 입력과 연결.
- 현재 scrypt 해시·매개변수 SQL·서버 권한 검증·한국어 오류 유지.
- DB 스키마 및 API 계약 변경 없이 기존 서비스 동작을 재사용.
- 현재 화면 구성과 수동 목록 갱신 유지.
- 공식 스킬 원문을 Codex 프로젝트 경로에 보존하고 도구 호출 차이만 지침에 명시.

## Testing Decisions

사용자 확인 전 제안 상태.
기존 브라우저 CRUD/API 테스트를 주 검증 지점으로 사용한다. 화면에서 분실 안내,
PC·모바일 CRUD·오답 거부·새로고침 영속성을 확인한다. 동명이인 두 글을 서로 다른
비밀번호로 작성하고 교차 수정·삭제 거부를 기존 서비스 통합 테스트에서 확인한다.
내부 함수 호출 횟수나 구현 구조를 테스트하지 않는다. 기존 SQL·공백 처리 테스트를
재사용하며 새 DB·과도한 목(mock)은 도입하지 않는다. 공개 배포 테스트 글은 삭제한다.

## Out of Scope

재작성, 디자인 개편, 자동 실시간 갱신, 로그인, 관리자, 비밀번호 복구,
이름 수정, DB 교체, 불필요한 데이터 마이그레이션.
